| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |

---

## Reporting a Vulnerability

The REDRECON-X development team and author take security vulnerabilities and responsible disclosure seriously.

If you believe you have discovered a security issue within REDRECON-X:
1. **Do NOT open a public GitHub Issue.**
2. Send a confidential report to the project maintainer:
   - **Email**: `security@anandbinuarjun.com` or via GitHub Private Vulnerability Reporting on [AnandBinuArjun/REDRECON-X](https://github.com/AnandBinuArjun/REDRECON-X/security/advisories/new).
3. Please include:
   - Detailed description of the vulnerability.
   - Proof-of-concept (PoC) code or steps to reproduce.
   - Potential impact on the host system or scanned targets.
   - Suggested remediation or patch if available.

We commit to acknowledging your report within **48 hours** and providing regular updates throughout the investigation and remediation lifecycle.

---

## Ethical & Authorization Boundaries

REDRECON-X is designed strictly for:
- Systems you own.
- Systems you have explicit, written authorization to assess (e.g., formal penetration test engagement, bug bounty program scope, academic research range).

Scanning systems without authorization is illegal under computer misuse legislation worldwide.
